# src/sofle_case/

## Purpose
The core `sofle_case` Python package. Contains all parametric geometry (tray shell, standoffs, battery pocket, switch-plate membrane, MCU canopy, encoder plateau), constants, PCB data loading, and phantom visualisation helpers. The primary entry points are `case.py::build_top_part(side)` and `build_bottom_part(side)` — the two printable halves of the **sandwich clamshell** (a deep TOP tub + an inset BOTTOM plate that join via a **rabbet**, screwed together through the standoffs). `build_case_half()` is the legacy single-piece tray.

## For AI Agents

### Working In This Directory

**Before touching any file, read `constants.py` first.** All geometry is driven by constants — never hardcode a dimension inline.

Key invariants to preserve:
1. `PCB_TOP_Z == PCB_SEAT_Z + 1.6` — derived, do not break.
2. `PLATE_TOP_Z == PLATE_SEAT_Z + 1.6` — derived, do not break.
3. `MAIN_RIM_Z == PLATE_TOP_Z` — minimal short case: the tray walls end flush with the plate top, no hill. (The canopy + encoder plateau rise above this, but they are fused on in `case.py`, not part of `tray.py`.)
4. `tray.py` must produce **exactly 1 solid** — `test_tray_is_single_solid` guards this. Both sandwich parts (`build_top_part`/`build_bottom_part`) must also each be a single valid solid — `test_split_parts_are_valid_single_solids`.
5. No wall rises above the tray's `rim_z` (default `MAIN_RIM_Z`; the sandwich tub deliberately passes `COVER_TOP_Z`) — `test_no_wall_above_rim` guards the default flat-wall tray.
6. Rabbet fit is set by `SEAM_FIT_CLEAR` (0.2 mm XY) / `SEAM_LEDGE_CLEAR` (0.3 mm Z) — the parts nest with clearance (zero interference); the screws + standoffs, not the rabbet, set the clamp and precise registration.
7. The nano's Y extent comes from `MCU_BODY_N_Y` / `MCU_BODY_S_Y`, **never** `MCU_POS ± MCU_BODY_L/2`. `MCU_POS` is the pin-array centre, and the board is anchored at its USB end — a longer board grows southward. Centring it instead drives the USB jack into the canopy's north wall. Guarded by `test_mcu_board_is_anchored_to_its_pin_array_not_centred_on_it` and `test_usb_jack_stops_short_of_the_north_wall`.
8. The USB-C jack is **mid-mount** (`USB_JACK_H` 3.16 / `USB_JACK_SINK` 1.00): it straddles the nano board, so both jack bands derive from the board faces and differ per orientation. Never model it as a top-mount part sitting on the board.
9. The USB port is a **stepped bore** — overmold pocket (`CANOPY_USB_OM_*`) outside, shell neck (`CANOPY_USB_W` / `canopy_usb_z`) inside — because the jack mouth sits 4.41 mm behind the outer face and a straight hole gives 34% shell engagement while blocking the overmold. Probe each section at its own depth; a mid-wall Y lands inside the pocket.
10. The canopy ridge is derived **per half** via `canopy_ridge_top_z(side)` — never assume a shared height. `CANOPY_RIDGE_TOP_Z` still exists as `max(canopy_ridge_top_z(s) for s in ("left","right"))`, but it is a trap for anything that cares which half it's building; the only legitimate use is `case._slide_scoop`'s cut ceiling, where over-reaching on the shorter half is harmless. Each half's pocket must clear `CANOPY_NORTH_ROUND_R` against its OWN ridge — `test_usb_pocket_stays_buried_under_the_north_shoulder[side]`. `_canopy_roof_z` and `_roofline` take `z_ridge` with **no default**, on purpose: a caller that forgets to pass the per-half ridge silently samples the wrong half's roof surface.
11. `CANOPY_RAMP_SAMPLES` is **25, and that is a CEILING — do not raise it.** Too low rings (9 overshot the analytic smoothstep by 0.14 mm while still passing the monotonicity test, which does not check flatness); too high detonates the mesh, because OCC tessellates by **curvature**, not deviation, and a denser interpolating spline trades deviation for high-frequency curvature wiggle. Measured on the right half: 28k triangles at 9, 39k at 25, 216k at 41, **397k at 51** — a 2.5 MB → 39.9 MB STL to buy 0.023 mm of flatness already 10× under a 0.2 mm layer. The left half never blows up (its ramp is 2.76 mm shorter, so mild curvature), so **measure the RIGHT half**. `test_canopy_ramp_mesh_does_not_detonate` bounds this; nothing caught the 51 regression because every geometric assertion passed — the shape was fine, only the mesh was absurd.
12. The canopy's west top shoulder facet is a **swept boolean** (`_chamfer_west_top`), never a 3-D edge `chamfer()`. OCC rejects an edge chamfer on that run once the ramp `Spline` carries more than ~9 control points, and the old `_round_west_top_edges` swallowed the failure with a bare `return part` — so raising `CANOPY_RAMP_SAMPLES` to 51 silently deleted the facet, and no test caught it. The boolean ruled-lofts a cutter from the body's own roofline, so it is density-independent (verified at 9/13/21/51/81) and it **asserts** that it removed material. `chamfer_v` is the vertical leg, `chamfer_h` the inboard one — explicit now, because the old 3-D call let OCC pick and it picked the reverse.
13. The canopy's NW top corner is a **cylindrical round** (`_round_nw_corner`) at the case's own corner radius. It was briefly a flat diagonal chamfer to escape a measured 64.7° kink (OCC patching the seam with CONE/BSPLINE surfaces); that kink was real but **misattributed** — it only appeared because the west shoulder facet above was silently missing, leaving the cylinder to meet a raw square shoulder. With the facet cut, the corner is exactly one `CYLINDER` face. `test_canopy_nw_corner_is_rounded` pins `kinds == ["CYLINDER"]` on both halves. Lesson: before redesigning a feature to fix a seam artifact, confirm its *neighbours* are actually being built.

14. The canopy roofs carry **puzzle strokes**: two CURVES drawn across the ASSEMBLED pair, each crossing BOTH canopies, so the four strokes are really two curves and the mark completes only when both halves are on the desk. Each mark is its fitted line plus a lateral profile, `d = A·v³` with `v` measured from the seam and `A = PUZZLE_CURVE_A` (4.75 mm) at the span's end. Three properties follow and all three are tested. (a) The halves **cannot** look alike — one curve meets each canopy at a different angle because they are splayed, so "right must not mirror left" is arithmetic, not a table of tuned numbers (chord dx/dy: line 0 is +1.417 on the left against +0.083 on the right; line 1 is −2.617 against −1.548). (b) Continuity across the gap is **exact** (~1e-14 mm): every vertex of both halves lies on ONE assembled polyline, because both halves are sampled from one shared `t` grid and then clipped, rather than being aimed at each other. That is the curved successor to the straight version's exact collinearity and it must stay exact for the same reason — if the number ever becomes merely small, someone has replaced the derivation with transcription. (c) The sampled polyline **is** the analytic cubic, to `PUZZLE_CHORD_SAG` (measured 0.012 mm) — a separate claim with its own number, because (b) would still pass on a coarse polyline. `canopy_puzzle` owns the assembled-frame definition and the BASELINE is **fitted from the design sketch**, not invented — the sketch was measured by pixel classification + PCA + a Hough split, its stroke pairs matched in page space to 0.11°, and one splay plus two lines fit all four strokes to **0.166 mm max / 0.124 rms**. Fitting rather than transcribing was deliberate: the four measured strokes individually imply 48.6° of splay from one pair and 50.8° from the other, so transcribing would bake that 2° disagreement in permanently instead of surfacing it as a residual.

    **The bend is at the seam, and that is what keeps the design's promises.** The profile is an ODD CUBIC about the seam, so it is zero, flat AND has zero curvature exactly where the two halves hand over: the pair joins along the baseline's own direction, misplacement costs what it always cost, and the curvature is spent out on the roofs where there is nothing to compare it against. It also means the mark's plan-space consequences are unchanged near the gap — line A leaves the north wall essentially AT the seam (t −76.9 against the seam's −75.9, profile −0.0002 mm), so the amplitude cannot spend the NW-corner clearance however bold the mark gets further out. Outside the fitted span the profile continues **tangentially (C1)**, never clamped: a clamp would put a slope discontinuity within a break's length of the terminals that run off the arrises, i.e. in the one place the eye follows the mark off the part. `PUZZLE_CURVE_A = 0` is not "nearly straight" — it IS the straight layout, back to two points per stroke and within 1.4e-14 mm of the fitted lines, which is what makes the amplitude a dial with a meaningful zero.

    **`PUZZLE_CURVE_SPAN` decides what the amplitude MEANS, and its provenance is load-bearing.** `u` normalises `t` over the span the marks occupy and `u_seam` says where the gap falls along it; both come from the **shipped STRAIGHT layout** (`straight_strokes` + `canopy.straight_puzzle_strokes`, breaks and the sketch's trims included), never from the raw safe-region chords. Derived from the chords instead, line A's span is 89.5 mm with the seam at u 0.72, and the same A = 4.75 then produces a 0.4 mm departure — a mark that is visually straight. The values are **pinned and re-derived** (`span_from_straight`, asserted to 1e-6), because a pinned number nobody re-derives quietly becomes a fiction. They are also width-sensitive in a way that is easy to miss: every break is one groove width long, so narrowing the groove 1.6 → 1.0 pulled all four terminals in by 0.6 mm and moved the span with them (line A: −107.436 → −107.741, u_seam 0.507 → 0.516). Nothing the CURVE is allowed — the ramp-foot bound, the dropped trims — may feed back into it, which is why `_puzzle_strokes` passes those as `extra` to the curve only.

    **The amplitude is the one chosen number in the module, and it was chosen knowing what it costs.** 4.75 mm, parallel hands, picked by eye in a browser lab against the real roof outlines. Measured on the real geometry: min radius 46.8 / 47.7 mm; left A 27.0 mm, left B 24.4, right A 64.0 (the full ramp), right B 31.4. Two things the straight mark had are gone and both were accepted deliberately: the east arris is now notched **once in the pair** (right half) instead of once per half — the bow lifts the left half's line A 3.2 mm short of that wall — and right A dies at y 59.6, clipped by the WEST edge 0.8 mm short of the ramp foot rather than landing on it. `A ≈ 2.10` is where "nothing is given up" ends: it keeps both notches and lands right A exactly on the foot at 58.8 (min radius 86 mm), at a peak departure of 2.1 mm. It was offered and declined — the mark is the point. Mirrored hands at 4.75 keep both notches but pull right A off the ramp entirely (it stops at y 83.1), costing the ramp crossing the normal-offset cutter exists for. `test_the_pair_keeps_exactly_one_east_break_and_the_amplitude_is_what_cost_the_other` pins the loss AND attributes it, by checking the same stroke does reach the wall at A = 0.

    **Where each stroke stops was measured too (`PUZZLE_STROKE_COVER`), and is no longer cut.** The sketch's per-stroke coverage of its own chord (left 0 = 1.007, left 1 = 0.666, right 0 = 0.502, right 1 = 1.006) was measured by RANSAC-splitting the white stroke pixels and comparing each stroke's extent with its line's chord clipped against that shape's oriented box; stated as a **fraction** because a ratio along a line is affine-invariant, so it needs no page→mm transform. The trims are not applied to the cut geometry any more — right 0 needs its full run to reach down the ramp at all, and left 1 goes 15.4 → 24.4 mm without it. They survive in the module because the SPAN is derived from the layout that includes them; `straight_strokes` therefore has to keep every term the sketch had.

    A stroke **crosses the ramp** — two do now (left line 1, right line 0) — which is why `_puzzle_cutter` clips the footprint prism against a **normal-offset** roofline instead of dropping a fixed depth in Z. `_offset_roofline`'s slopes must come from `_roofline_slope` (the **analytic** derivative of `_smoothstep`) — a one-sided finite difference at the foot reads the ramp's first 0.06 mm of rise as a slope, pushes the offset endpoint north of `CANOPY_RAMP_FOOT_Y`, and `_yz_prism`'s span filter then drops the south face so the sketch will not close.

    **`CANOPY_PUZZLE_DEPTH` is a CAP, not the depth: `puzzle_depth_at(y)` is.** The cavity is a straight Z offset of the roofline, so perpendicular to the surface — the direction a groove eats — the shell is only `CANOPY_ROOF_WALL·cos θ`: 1.23 mm at the right half's steepest 34.9°, where a full 0.5 mm groove leaves 0.73 mm of a roof that is supposed to keep 1.0. Near the foot the binding term is the MEMBRANE instead: the foot lands on the cover surface and the body's base is one cover thickness below it, so the depth reaches **exactly zero** at `CANOPY_RAMP_FOOT_Y` — derived from the two ceilings against `CANOPY_PUZZLE_MIN_ROOF`, never a hand-set fade. Measured on the right half: 0.000 at the foot, 0.230 at the steepest point, 0.500 from the ramp top northward; the left half bottoms out at 0.333 because its ridge is 2.76 mm lower — the halves differ here as a consequence, not as a tuning. Both ends' gradients vanish with `_roofline_slope`, so the offset profile arrives horizontal at the foot and at the ramp top, which is exactly the tangent `_yz_prism` forces on its `Spline`; a multiplicative taper would ring there. The field lives in the shared `under` solid rather than per stroke, so depth cannot desynchronise between strokes and any stroke that strays onto the ramp gets the legal depth automatically. Because the depth dies at the foot, the strokes are allowed 1.5 mm further south than the old keep-out (`y0_ramp`) — a groove that has already faded to nothing cannot spill onto the cover.

    **Terminals: three kinds, and each end is exactly one of them.** (i) **Off an edge** — west and north behave identically, and that is the design: the stroke is aimed a break's-worth PAST the wall, the cutter's floor stays flat (`_offset_roofline` covers the roof only), and the groove holds full depth to the facet's top line then fades as the facet drops from under it. (ii) **East** — the upper stroke of the RIGHT half breaks THROUGH the east arris (`CANOPY_EAST_X + CANOPY_PUZZLE_EAST_BREAK`); sharp, no facet, genuinely notched. (iii) **Free** — a terminal that stops in open roof, which is what the left half's line A now has.

    Judgements about where the north mark leaves the part are made at the WALL, via `puzzle_north_crossings`, never at the terminal: the stroke is tilted, so a break's-worth of overshoot also slides the endpoint 0.2 mm west per mm — a position the groove never occupies. `puzzle_north_crossings` and `_puzzle_north_exit_ok` walk each stroke **segment by segment**, so a polyline that crossed the wall twice would be reported as two crossings rather than silently read as a chord; the pocket-band check is on the TERMINALS, because a stroke that merely passes through the band on its way out is the case the exit window exists to allow. **The crossing TILT is applied in `_puzzle_north_exit_ok`, not in the window**: the groove's footprint along the wall is `(w/2)/sin θ` per side — 0.51 mm at line A's 78.6° — and the window states the keep-out without knowing the angle.

    **Carrying the offset down a facet was built and reverted.** `_offset_roofline` could follow the north facet (it belongs to the same Y–Z sweep as the roof, unlike the west one, which is cut along X), giving 0.5 mm normal all the way through the band and a notch in the wall. It worked and it looked wrong: the mark reads as being dragged down the slope where the west ends run off cleanly. Two edges treated alike beats one edge treated thoroughly. It also cost an over-cut — mitring two offset half-planes at that convex junction deepens the groove 0.500 → 1.118 mm over the 0.31 mm before the facet, because the true erosion there is an arc, which runs backwards in Y and cannot be expressed in a Y-ordered profile.

    **`PUZZLE_LINE_NUDGE` is the one number in `canopy_puzzle` that is NOT from the sketch.** Line A is translated 3.3 mm perpendicular to itself: as fitted it left the right roof 1.3 mm from the NW corner, inside the cluster of invariant 15. A translation changes no angle and no relationship between the halves, so continuity survives it exactly (~1e-14) and both halves move together — but 3.3 mm is ~20× `PUZZLE_SKETCH_RESIDUAL`, so line A no longer lands where the drawing puts it. Kept as a separate term, never folded into `PUZZLE_LINES`, so "fitted from the sketch" stays literally true of everything else and this can be zeroed in one edit. The value is bounded on both sides and neither bound is taste, all measured at the **wall crossing** on the curved mark at the 1.0 mm width: ≥ 2.65 for the whole groove width to leave through the *straight* north edge (the corner arc is tangent at `CANOPY_WEST_OUTER_X + CANOPY_CORNER_R`), ≤ 4.42 before the crossing crowds the USB pocket. Scanned at 0.1 the break is open from 2.7 to 4.4 and refused either side. At 3.3 the margins are 0.66 mm (corner, tilt included) and 2.17 mm (pocket); the window's middle is 3.54. The old ≈4.6 ceiling — where the LEFT half's line A stopped breaking the east arris — no longer binds, because the amplitude has already spent that break. `canopy_puzzle_north_exit_window` states the window in the module that owns the keep-outs, the north break is refused outside it, and two tests pin both ends — including that zeroing the nudge puts the exit back in the corner (x 11.55), so the departure cannot survive as a no-op.

    Which stroke is "upper" is DERIVED — `canopy_puzzle.upper_index`, northernmost by midpoint of its **safe-region chord**. It must be answered *before* breaks and trims: breaks lengthen and trims shorten, so a midpoint taken from the finished segments names the other stroke on the right half and would move the east break to the wrong one. That is a real bug that was caught by a test, not a hypothetical. `north_index` is the same question asked of finished strokes and takes the **mean of the vertices**, not the chord midpoint, which on a bowed mark disagree by over a millimetre.

    **The groove is 1.0 mm wide, and `ENCODER_GROOVE_W` deliberately no longer follows it.** A curve reads as a drawn line at a narrower width than a straight slot does — 1.6 mm of curve on an 18 mm strip reads as a channel — and the north exit is scored against the groove's own width, so narrowing it is what buys the corner clearance (tilt-corrected NW margin 0.36 → 0.66 mm). 1.0 mm is 2.5 extrusion widths at a 0.4 nozzle, the floor for a groove that reads as a line rather than a scratch. The encoder deck's straight groove keeps 1.6 for the opposite reason, and the two are now separate numbers rather than a copied one so neither can drift while pretending to agree.

    Ends are **square**, never rounded, and the cutter is a polygon band (`_band_prism` + `_band_offsets`): the polyline is offset ±w/2 along each station's own normal and extruded in Z, so the ends stay perpendicular to the local tangent and **every face added is planar** — the curved marks cost 62.3k triangles against 61.8k bare, and no cylindrical face can appear, which is what `test_no_terminal_is_rounded` is really guarding. `_band_offsets` carries the plan-space twin of `_offset_roofline`'s fold-over assert (at R ≈ 46 mm against a 0.5 mm half-width the margin is ~90×, so it guards a future re-draw, not today). Guarded alongside it: `test_the_east_arris_is_broken_at_most_once_per_half` (the notch AND the intactness of the rest of that arris, with the expected count derived from the strokes), `test_no_stroke_crosses_a_chamfer_top_line`, and `test_every_stroke_runs_out_at_the_gap_side`. Note `test_canopy_west_top_facet_runs_the_whole_shoulder` builds `puzzle=False`: the stroke that breaks the east arris otherwise reads as a broken east edge inside its 2.0 mm window.

15. **The canopy's two top facets share an angle, not a size — and the north one is DRAWN, never cut with `chamfer()`.** West shoulder: 1.2 mm run / 2.4 mm drop, top line x = 11.7. North top: **0.5 / 1.0**, top line y = **121.0**. Both are the case rim's 2:1 drafted style (`RIM_FACET_RUN/DROP`); measured on the bare part, the north band drops 0.36 / 0.76 mm at y = 121.2 / 121.4, i.e. slope 2.0.

    **Why the north one is smaller, and why that is not a free choice.** Its DROP eats the north wall's top, and the USB overmold pocket sits right under it: `canopy_ridge_top_z` sizes the roof against that pocket assuming the top edge eats exactly `CANOPY_NORTH_ROUND_R` (1.0, a historical name — that edge was a round once). So the facet's drop *is* that budget, and `canopy_north_chamfer` asserts the result leaves `CANOPY_USB_OM_ROOF_MIN` over the pocket — it comes out at exactly 0.50 mm on both halves. Matching the west facet leg-for-leg (2.4 drop) puts the wall's outer face **0.9 mm below** the pocket, i.e. the port mouth opens into the facet, and buying that back costs **+1.40 mm of ridge on both halves**. The run then follows from the rim proportion, so the bands differ in size but not in angle — the match that was actually available.

    **This shipped wrong for a while, and the mechanism is worth remembering.** `_yz_prism` used to hand OCC `chamfer(length=chamfer_v, length2=chamfer_h)` inside a fallback loop that tried `(l1,l2)`, then `(l2,l1)`, then the symmetric leg, accepting **whichever did not throw**. It never threw — and it applied the legs reciprocally, giving 2.4 run / 1.2 drop, the mirror of the intent, with the north top line at 119.1 instead of where the constants read. Nothing failed; a wrong-but-successful chamfer is invisible. It is now two explicit points in the profile polyline plus an assert that they are where they were asked for. `_chamfer_west_top` was always immune for the same reason: it builds its facet as an explicit swept boolean. See `occ-chamfer-leg-order`, and do not reintroduce a 2-D `chamfer()` on a profile vertex without measuring the result.

    `canopy_north_chamfer_run` is the single place consumers ask where the flat roof stops on the north side — it is NOT `canopy_top_chamfer`'s leg.

**Phantom modules** (`pcb_phantom.py`, `plate_phantom.py`, `switch_phantom.py`) are visual only. They must not be imported by structural modules. Guard all phantom imports inside `if __name__ == "__main__":` blocks.

### Common Patterns

**build123d style:**
```python
from build123d import Part, BuildPart, Cylinder, Mode, Locations
from . import constants as C

def my_feature(at: tuple[float, float]) -> Part:
    x, y = at
    with BuildPart() as bp:
        with Locations((x, y, some_z)):
            Cylinder(radius=C.SOME_DIA / 2, height=C.SOME_H)
    assert bp.part is not None
    return bp.part
```

**Coordinate systems:**
- Case coords: origin at outer lower-left corner, Z=0 at outer bottom face.
- PCB coords: KiCad convention (Y down). Use `C.pcb_to_case(x, y)` to convert.
- Empirical constants in `constants.py` are geometry-tuned — change with care and re-run tests.

**OCP viewer block (required on every geometry module):**
```python
if __name__ == "__main__":
    from ocp_vscode import show
    show(my_feature(...), names=["my_feature"])
```
